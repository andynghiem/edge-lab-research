# Security Policy

EDGE LAB Research should never require contributors to publish secrets, private keys, exchange credentials, wallet seed phrases, account exports or private infrastructure details.

## Do not open a public issue for

- exposed API keys or credentials;
- wallet private keys or seed phrases;
- vulnerabilities that could immediately put funds or users at risk;
- private endpoints or access tokens;
- personal account data.

If you discover sensitive material accidentally committed to this repository, contact the maintainer privately before posting exploit details publicly.

**Contact:** `Andynghiem@gmail.com`

## Research vulnerabilities

Market-structure research sometimes overlaps with protocol or exchange vulnerabilities. EDGE LAB is interested in understanding mechanisms, not harming users. If a finding could be actively exploited against a protocol, exchange, wallet or user, use the affected project's responsible-disclosure process first.

## Public data principle

Published case studies should use public, unauthenticated data wherever practical. Reproduction instructions must not depend on another person's credentials.
